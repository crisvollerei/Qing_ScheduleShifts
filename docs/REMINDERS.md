# 上班提醒

Android 应用左下角有固定的「上班提醒」入口。设置页复用网页的银昼 / 蓝夜主题、按钮、静态输入页与返回键行为；普通浏览器不显示此入口。

## 本应用闹钟

启用开关、选择提前量并保存后，持续为当前排班的工作班次安排闹钟。提前量为 0–1440 分钟，提供 15 / 30 / 60 / 120 分钟快捷选择。铃声与振动至少保留一项，可调用系统铃声选择器。

不需要设置覆盖天数，也不依赖桌面小组件。页面显示已登记的下一次提醒、对应上班节点与授权状态；「待授权」「安排失败」「暂无工作班次」不等同于「已安排」。修改后的设置必须保存才生效。

调度使用 `AlarmManager.setAlarmClock()` 的一次性闹钟，预先登记后续最多八个节点，到点后补充后续节点。它不是网页定时器，也不是系统时钟应用里的记录。未响铃时没有持续运行的服务；触发后由媒体播放前台服务播放闹钟、振动，并提供通知和锁屏停止入口。最长持续五分钟，不自动无限重启。

锁屏响铃页使用独立任务，不与排班主页面共用任务栈，也不显示在最近任务中。停止闹钟或超时结束时，页面撤销锁屏覆盖、亮屏与保持屏幕开启状态，并移除自己的独立任务，将界面控制交回系统；不会代替用户解锁，也不会主动打开排班主页面。返回键只关闭响铃页，仍可通过通知停止闹钟。

排班、方案或提前量改变后，取消旧安排并重新计算。关闭后取消待触发的本应用闹钟与测试闹钟，并停止当前响铃；不操作外部时钟与日历。节点带调度版本并记录消费状态，过期广播或重复广播不能重复响铃。已错过的提醒不立即补响；系统迟到超过十分钟的广播跳过。

跨日提前量按实际时间扣减。例如明天 00:30 上班、提前 60 分钟，提醒时间是今晚 23:30。工作日期和跨日班次规则与网页、小组件共用同一份定义，不通过倒计时显示文字反推。

## 权限与可靠性

- **闹钟和提醒**：Android 12+ 按系统要求授权。未获得权限时不悄悄降级成非精确任务。
- **通知**：Android 13+ 请求通知权限，同时检查通知总开关及上班闹钟通道。未允许时不登记本应用闹钟。
- **锁屏全屏显示**：Android 14+ 可能需要额外允许；可选，未允许时仍提供闹钟通知和停止入口，但不保证自动弹出全屏。
- **后台运行**：部分系统需要用户允许后台运行、自启动，或解除电池限制；页面提供应用设置入口，不自动改变这些系统选项。
- **日历**：仅在用户点击日历授权入口时请求读写权限；本应用闹钟和系统时钟交接不需要日历授权。

普通页面退出、进程因内存被回收、锁屏和标准休眠不要求网页持续运行。重启、应用更新、系统时间或时区改变、精确闹钟授权及重新打开应用时重新核对安排。重启后需要首次解锁，才能读取凭据保护存储中的排班。

强行停止、厂商冻结或后台限制、权限撤销、手机关机仍可能使提醒失效。准时触发不代表声音一定可听见，还受闹钟音量、铃声资源、勿扰和设备音频状态影响。不能承诺所有手机都支持关机闹钟。

「30 秒后测试」使用已保存的铃声与振动设置，可关闭页面、锁屏后测试，并可单独取消。测试成功不等于锁屏过夜、重启或厂商省电模式均已验证。

## 系统时钟

「核对下次提醒并打开时钟」先显示计算结果与日期风险，再调用系统创建闹钟界面，由用户确认并保存。打开时钟只代表交接成功，不等于闹钟已经创建。

安卓通用 `ACTION_SET_ALARM` 接口提供时、分与每周重复日，不提供统一的年月日或到期时间。不得把每周重复当成有限日期范围。因此该入口不提供跨品牌保证有效的未来 N 天批量创建；若系统时钟不能选择目标日期，应取消并改用其他方式。

系统时钟保存后由它管理，不随本应用开关或排班变化自动更新、删除。它的通知、铃声与电池策略由系统时钟自身控制。

## 系统日历

选择可写日历，再选择从明天起 1 天、7 天或自定义 1–90 天。范围按上班日期计算，只生成工作班；已错过的提前提醒会在预览中说明并跳过。夜班保留跨日结束时间。

先预览班次、提醒时间和数量，再确认生成。预览绑定排班、提前量和目标日历；发生变化需要重新预览。一次生成不滚动补齐、不自动续期，排班变动后需再次生成相应范围。

本机保存事件 ID、日期、目标日历与唯一归属标记。重复生成更新同日期事件及提醒，不重复叠加；所选范围内不再上班的已管理事件会移除。其他日程不受影响。

「清理本应用导出的事件」只处理本机仍有管理记录、且事件仍含匹配归属标记的日程，包括历史事件；手动删除标记的事件不会自动清理。删除应用数据或换机后不能保证找回原管理关系，必要时在系统日历中手动删除。日历批量操作成功但本机记录保存失败时会明确提示需手动核对。

日历提醒通常是通知，不保证持续响铃。事件由用户选择的日历与账户管理，可能同步到其他设备；提醒效果取决于日历应用的提醒、通知和同步设置。

## 数据与模块

`ReminderSchedule` 复用原生排班模型；`WorkReminders` 与 `WorkReminderReceiver` 管理独立闹钟；`WorkAlarmService` / `WorkAlarmActivity` 负责响铃和停止；`ReminderCalendar` 管理显式日历导出；`ReminderBridge` 串行处理网页请求并回传实际结果。

排班读取 `WidgetSettings` 的 `cycle` / `anchorDate` / `shiftDefs`。提醒开关、提前量、铃声、调度与日历管理记录使用独立的 `WorkReminders` 偏好，不进入网页排班备份，不修改小组件的倒计时或刷新调度。

三种方式独立使用，也可组合；组合可能重复提醒，关闭本应用闹钟不会清理另外两种记录。提醒不需要本应用联网，但所选日历账户可以由系统自行同步。
